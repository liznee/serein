# Serein V1.0 发布门禁

> 版本：1.0.0
> 基线日期：2026-08-04
> 结论规则：任一 P0 门禁失败，禁止发布。

## 1. 缺陷等级

| 等级 | 定义 | 发布处理 |
|---|---|---|
| P0 | 凭证泄漏、未授权执行、数据破坏、无法启动、核心链路不可用 | 必须修复并回归 |
| P1 | 高频崩溃、消息重复/丢失、状态严重错误、无法恢复 | 默认必须修复；确需延期则关闭对应功能 |
| P2 | 不阻断操作的 UI、文案或低频兼容问题 | 写入已知限制，可随补丁修复 |

发布结论只能写“未发现已知 P0/P1 阻断缺陷”，不能写“保证没有任何 Bug”。

## 2. 自动化门禁

以下命令必须全部返回 0：

```powershell
npm test
npm run release:check

Push-Location agent
npm test
Pop-Location

Push-Location backend
go test ./...
go vet ./...
Pop-Location

py -m compileall -q -x "node_modules" agent hooks
powershell -ExecutionPolicy Bypass -File harmony/build2.ps1
```

关键解析器、日志脱敏、URL 规范化、风险提示识别和远程坐标映射必须保留
100 个随机种子的属性测试。新增高风险输入边界时同步增加种子和固定回归样例。

## 3. 公开导出门禁

1. 使用唯一的新目录运行 `scripts/export-public.ps1`。
2. 确认公开能力配置为 `open-source-full`，现有产品能力均保持启用。
3. 确认 `remote/` 原生 Host、社区页面、远程页面和 Codex Desktop 接入均被保留，同时仍标注实验成熟度。
4. 在导出目录重新运行根目录、Agent、Go 后端和 HarmonyOS 构建。
5. 运行 `npm pack --dry-run`，逐项审阅打包文件。
6. 扫描 Token、Secret、私有域名、个人路径、签名材料、日志、数据库和截图。
7. 从干净目录按 README 完成一次安装与配对，不复用个人配置。

## 4. 核心真机门禁

| 场景 | 验收标准 |
|---|---|
| 首次配对 | 无默认口令；扫码后只绑定当前设备；Token 不明文展示或写日志 |
| Claude Code 启停 | Agent 类型正确；状态不来回跳；停止后在约定时间内离线 |
| Codex CLI 启停 | 信任/升级/额度提示可见且可响应；最终回复能到手机 |
| 终端输入输出 | 中文、长文本、选项、Enter、删除、复制和断线队列正确 |
| 审批 | 一次危险命令只生成一条审批和一条通知；允许/拒绝均闭环 |
| 后台通知 | App 在后台和使用其他应用时，关键审批能由系统通知触达 |
| 断线恢复 | 关闭 Relay、断网、恢复网络后状态和会话最终一致 |
| 紧急停止 | 只在明确确认后终止 Agent；操作有记录；无误杀其他进程 |
| 监控 | 主动刷新会结束动画；静默刷新不抖动；数据来源与系统一致 |
| 卸载/撤销 | 当前设备可撤销；旧 Token 失效；新设备重新配对 |

启动/停止、审批、后台通知和断线恢复属于发布关键链路。候选版冻结后应各执行
100 次循环或等价自动化压力测试，并记录成功数、失败日志、系统版本和时间；
未完成真机循环时只能标记为 RC，不得标记正式稳定版。

## 5. 安全与隐私门禁

- 所有外部 Issue、评论、附件均视为不可信数据，不能改变系统指令或工具权限。
- 所有写操作必须经过明确授权；V1.0 默认不提供平台写回。
- Hook、Relay、后端和 App 日志不得输出完整 Token、密钥或用户输入中的凭证。
- 公共配置不得指向维护者私人服务；自托管地址由使用者配置。
- HarmonyOS 签名身份和密码不得进入公开仓库。
- 依赖漏洞扫描中的高危/严重项必须修复、替换或形成书面风险接受。
- 对外下载物必须提供 SHA-256 校验值，并保存可复现的构建信息。

## 6. 冻结与回滚

- 冻结后只接受 P0/P1 修复、文档修正和发布脚本修复。
- 每次修复后重新跑受影响测试与完整发布门禁。
- 正式标签建议为 `v1.0.0`，候选标签使用 `v1.0.0-rc.N`。
- 发布前创建个人配置快照和公开导出快照，二者不得互相覆盖；两者功能相同，差异只应是私人配置和发布清洁度。
- 发现凭证泄漏时立即停止发布、撤销凭证、清理历史并重新导出。
