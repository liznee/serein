# Serein V1.0 稳定性验证记录

## 1. 候选版本

- 验证日期：2026-08-04
- 版本：`1.0.0`
- 版本状态：Release Candidate，尚未标记正式 GA
- 工作区与公开候选能力集：`open-source-full`

正式 V1.0 的含义是“没有已知阻断级缺陷且所有发布门禁通过”，不是承诺软件永远
不存在任何缺陷。

## 3. 发布前仍需完成

- [ ] 连续完成 100 次红色审批，每次只出现一条通知且决定只生效一次；
- [ ] 前后台、锁屏和其他应用场景各完成通知回归；
- [ ] 在 AGC 登记 `com.serein.client` 的正式签名并开通 Push Kit，消除真机 `1000900010`；
- [ ] 更新 DevEco 调试/发布签名配置，并对当前工作区和全新公开导出各完成一次签名构建；
- [ ] 断网、恢复、后端重启和 Relay 重启后会话状态正确；
- [ ] 在一台没有个人配置的干净 Windows 环境完成安装；
- [x] 对当前 RC3 公开快照与 HAP 执行隐私扫描并生成校验和；
- [ ] 冻结 GA 提交后重新生成最终公开快照、HAP 和校验和；
- [ ] 人工检查 V1.0 所有页面不存在测试数据和个人信息，实验入口均有明确成熟度与授权提示。

以上项目完成并记录证据前，只能发布 `v1.0.0-rc.N`，不能声称“正式稳定版零 Bug”。

## 4. 已知边界

- Codex CLI 的结构化回复和工具步骤已适配，但工具审批兼容性仍弱于 Claude Code；
- 开源 V1.0 仅支持单设备绑定；
- 后台通知依赖用户授予系统通知权限以及自部署通知链路可达；App 进程被系统回收后的
  触达还依赖 AGC 应用身份、正式签名和 Push Kit 服务配置。2026-08-04 真机已验证代码会
  请求 Token 并自动重试，但当前应用身份返回 `1000900010`，因此该门禁尚未通过；
- 不可准确采集的监控字段必须显示不可用，不能使用估算值冒充真机数据。
